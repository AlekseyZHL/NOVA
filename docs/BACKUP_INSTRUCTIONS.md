# Инструкция по бэкапу (важно!)

Архив `NOVA-Wallet-v1.0.0-backup-2026-10-25.zip` содержит код, документацию и демонстрационную БД (`data/db.json`), но **намеренно не содержит секретов**:

- `.env`
- `data/vault.key`
- `data/session.key`
- `data/vault.enc`

## Почему так

Загрузка приватных ключей в облако — прямая дорога к краже средств. Ключ шифрования и зашифрованный master seed должны храниться **раздельно и офлайн**:

1. `vault.enc` — зашифрованный BIP-39 mnemonic. Без ключа бесполезен.
2. `VAULT_KEY` (32 байта hex) — только в KMS/сейфе/аппаратном носителе.
3. `SESSION_SECRET` — отдельно, ротируется независимо.

## Как сделать настоящий бэкап

```bash
# 1. Зашифруйте секреты одним паролем (openssl, пароль — только офлайн)
tar czf - .env data/vault.key data/session.key data/vault.enc \
  | openssl enc -aes-256-cbc -pbkdf2 -salt -out nova-secrets-2026-10-25.tar.gz.enc

# 2. Проверьте расшифровку ДО того, как удалять оригиналы
openssl enc -d -aes-256-cbc -pbkdf2 -in nova-secrets-2026-10-25.tar.gz.enc | tar tz

# 3. Сохраните зашифрованный файл на 2 независимых офлайн-носителях
# 4. Пароль — в сейфе / у доверенного лица, НЕ в том же месте
```

## Восстановление

1. Разверните код из source-архива.
2. `npm install`.
3. Восстановите `.env`, `vault.key`, `session.key`, `vault.enc` из зашифрованного архива.
4. `npm start` → в логах должен появиться **тот же отпечаток vault** (`3DEE3616` для превью).
5. Сверьте адреса: они выводятся детерминированно из seed и должны совпасть.

> Если отпечаток отличается — вы используете другой seed. Старые адреса и средства недоступны.

## Ротация

При подозрении на компрометацию: немедленно остановите выводы, создайте новый vault, переведите средства на новые адреса и ротируйте все токены (`BOT_TOKEN`, `SESSION_SECRET`, `VAULT_KEY`). См. раздел «Инцидент-респонс» в SECURITY.md.
