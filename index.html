ВОЗМОЖНОСТИ

Настоящая криптография,
а не «демо-кошелёк»

Ключи выводятся детерминированно, подписи можно проверить в любом эксплорере, а каждая отправка проходит через симуляцию и риск-движок.

🔐

Seedless-вход

Telegram initData проверяется по HMAC-SHA256 и timingSafeEqual. Дальше — зашифрованный вывод ключа по индексу пользователя. Есть запасной путь через #tgWebAppData.

🌐

Шесть тестовых сетей

Ethereum Sepolia, Base Sepolia, Arbitrum Sepolia, Polygon Amoy, Bitcoin Testnet4, Solana Devnet — живые балансы и курсы CoinGecko.

✍️

Реальные подписи

ECDSA через ethers v6, PSBT/P2WPKH через bitcoinjs-lib, ed25519 через @solana/web3.js. Поддерживается ERC-20 USDC.

🧠

Симуляция до подписи

/api/simulate считает газ/UTXO и возвращает HMAC-токен. /api/send сверяет параметры и повторяет проверки — подменить сумму нельзя.

🛡

Риск-движок

Лимиты в USD, белый список адресов, блокировка address poisoning, декодирование метода контракта, аудит-лог.

📱

UX как в приложении

Пять экранов, тема Telegram, QR-приём и сканер, своп, история, песочница, адресная книга, антифишинг-код, €/$.

ЧЕСТНО О РИСКАХ

Это MVP. И мы это не скрываем.

🔴 Что НЕ готово

Проект не проходил независимый аудит. Ключи хранятся на сервере — компрометация сервера означает компрометацию всех кошельков.

  • Нет KMS/HSM — master seed в зашифрованном файле
  • Нет PostgreSQL — конкурентная запись в JSON-файл
  • Нет rate limiting и настоящего MPC / соцвосстановления
  • Mainnet-своп отключён (501) до аудированного агрегатора
  • Не используйте для реальных средств.

🟢 Что уже есть

Криптография построена на проверенных библиотеках и покрыта офлайн-тестами, которым не нужны ни сеть, ни деньги.

  • 28 криптотестов: деривация, подписи всех трёх цепей, HMAC
  • 16 UI-тестов в jsdom + 4 теста запасного входа
  • Поддельная подпись и подмена confirmToken отклоняются
  • Секреты не попадают в Git: .gitignore + проверка в CI
  • Mainnet выключен (ALLOW_MAINNET=false)
АРХИТЕКТУРА

Пять шагов от нажатия до подписи

Ни одна транзакция не подписывается «вслепую»: между намерением пользователя и приватным ключом стоят проверки.

01

Вход

Telegram WebApp передаёт initData → HMAC-проверка → сессия на 7 дней.

02

Симуляция

Оценка газа / UTXO, декодирование метода, расчёт комиссии.

03

Риск-движок

Лимиты, белый список, anti-poisoning. Возвращает HMAC-токен на 120 с.

04

Подтверждение

Повторная сверка суммы, адреса и сети. Подмена = отказ.

05

Подпись и эфир

Vault расшифровывает seed, адаптер подписывает и транслирует в RPC.

EVM m/44'/60'/0'/0/i
BTC m/84'/coin'/0'/0/i
SOL m/44'/501'/i'/0'
ЗАПУСК

Три команды до работающего кошелька

Никаких API-ключей для старта: тестовые RPC и курсы CoinGecko работают сразу. Telegram-бот подключается отдельно.

terminal 
# клонируем и ставим зависимости
git clone https://github.com/AlekseyZHL/NOVA.git
cd NOVA && npm ci

# создаём .env с VAULT_KEY и SESSION_SECRET
npm run setup
npm start

# в другом терминале — 48 проверок
npm test && npm run test:ui && npm run test:entry

# или одной командой
make ci
